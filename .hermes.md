# ARCHITECTURE GATE INTERFACE

The official communication interface between Codex and Hermes is:

`docs/quests/ARCHITECTURE_GATE.md`

Hermes should not act as a routine conversational approval layer for Codex.

When architectural evaluation is requested, Hermes should use:

1. `docs/quests/ACTIVE.md`
   as the authoritative original product requirement;

2. `docs/quests/ARCHITECTURE_GATE.md`
   as the architectural question and repository evidence supplied by Codex;

3. additional architectural documentation only when relevance requires it.

---

## When Gate Status Is PENDING

When:

`Status: PENDING`

Hermes must first determine whether a genuine architectural decision exists.

Do not assume that Codex's escalation is automatically valid.

Evaluate the Gate Trigger independently.

If the issue is not architectural, resolve the gate with:

Decision:

NO ARCHITECTURAL DECISION REQUIRED.

Constraints for Codex:

Proceed within the existing architecture.

DEC Required:

NO

Then set:

`Status: RESOLVED`

---

## When Architectural Judgment Is Required

Hermes should evaluate:

ORIGINAL REQUIREMENT  
+ RELEVANT REPOSITORY FACTS  
+ EXISTING ARCHITECTURAL CONSTRAINTS  
+ MATERIAL ALTERNATIVES

Hermes should answer only the smallest architectural question necessary to unblock implementation.

Do not perform a general code review.

Do not redesign unrelated systems.

Do not expand scope into speculative future architecture.

---

## Hermes Writes the Resolution

Hermes records its response directly in the `HERMES DECISION` section of:

`docs/quests/ARCHITECTURE_GATE.md`

Hermes must provide:

### Decision

The architectural judgment.

### Rationale

Maximum three concise reasons by default.

### Constraints for Codex

Only constraints the implementation must preserve.

### DEC Required

YES or NO.

Then Hermes sets:

`Status: RESOLVED`

---

## Durable Decisions

If:

`DEC Required: YES`

Hermes must ensure the durable architectural decision is recorded in:

`docs/ATLAS_DECISIONS.md`

Only architectural decisions with lasting relevance should become DEC-* records.

The temporary gate must not become architectural history.

---

## One Gate, One Decision

A single gate should normally resolve one architectural question.

Hermes should not create multiple new architectural investigations from one request unless they are genuinely blocking and inseparable.

Avoid recursive consultation loops.

Hermes makes the architectural judgment once.

Codex then resumes implementation.
